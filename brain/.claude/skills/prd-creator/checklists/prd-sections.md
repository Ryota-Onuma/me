# PRD 深掘りチェックリスト

PBIからPRDを作成する際に、**徹底的に深掘りすべきポイント**のチェックリストです。

---

## 1. 背景と目的

- [ ] なぜこの機能が必要か説明されている
- [ ] 現状の課題が具体的に書かれている
- [ ] 目標が明確（測定可能だとなお良い）

**深掘り質問:**
- 今この機能がないことでユーザーはどう困っている？
- この課題を放置するとどんな悪影響がある？
- なぜ今このタイミングで取り組む？

---

## 2. ユーザーストーリー

- [ ] 誰が使うか明確
- [ ] 何をしたいか具体的
- [ ] なぜそれをしたいか理由がある
- [ ] 「[ユーザー] が [やりたいこと] できる」形式

**深掘り質問:**
- この機能を使うのは具体的にどんなユーザー？
- そのユーザーは今どうやってこの作業をしている？
- その作業の何が不満・不便？

---

## 3. 機能要件（最重要）

### 3.1 基本要素
- [ ] **誰が**: ユーザー、システムなど
- [ ] **何を**: 操作対象（データ、ファイル等）
- [ ] **どうする**: アクション（作成、更新、削除、検索など。アクションは具体的であること）
- [ ] **どうなる**: 実行後の結果・状態変化（結果は具体的であること）
- [ ] 「〇〇がXXできる」や「〇〇はXXする」のような主語述語の構造で書かれている

### 3.2 入力・出力
- [ ] 入力項目（必須/任意）
- [ ] バリデーション（文字数、形式等）
- [ ] 出力形式・表示方法

### 3.3 制約条件
- [ ] 件数制限
- [ ] 時間制限（有効期限等）
- [ ] 権限制約

### 3.4 エラーハンドリング
- [ ] 想定されるエラー種類
- [ ] エラー時の表示内容
- [ ] リトライ可否

### 3.5 エッジケース
- [ ] データ0件の場合
- [ ] 大量データの場合
- [ ] 同時操作の場合

### 3.6 既存機能への影響
- [ ] 既存機能の挙動変更有無
- [ ] データ構造の変更有無
- [ ] マイグレーション要否
- [ ] 後方互換性

### 3.7 UI/UX
- [ ] 画面配置
- [ ] 操作フロー
- [ ] ローディング表示
- [ ] 成功時フィードバック

### 3.8 スコープ外
- [ ] 今回含めない機能が明記されている
- [ ] ユーザーが期待しそうだが対応しないもの
- [ ] 将来追加予定だが今回は見送るもの

---

## 4. 非機能要件

- [ ] パフォーマンス要件（処理速度等）
- [ ] セキュリティ要件（認証、暗号化等）
- [ ] その他品質要件

**深掘り質問:**
- 処理速度の目標は？（○秒以内など）
- 認証は必要？
- データの暗号化は必要？

---

## 5. 最終チェック

- [ ] 全ての機能要件が「〇〇がXXできる」形式
- [ ] 背景と機能要件が一貫している
- [ ] スコープ外が明確で期待値のズレを防げる
- [ ] 開発者が読んで実装できる具体さがある

---

## 使い方

1. **PBI受領時**: このチェックリストで不足情報を特定
2. **深掘り中**: 各チェック項目を質問で埋めていく
3. **PRD完成時**: 全チェック項目を確認
