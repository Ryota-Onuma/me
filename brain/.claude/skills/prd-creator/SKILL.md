# PRD Creator スキル

## 目的
**PBI（Product Backlog Item）を入力として受け取り**、PRDに必要な情報の不足や曖昧な点を特定し、徹底的な質問で深掘りして、**最高品質のPRD**を作成します。

## 基本原則

1. **PBIから始める** - ユーザーが持っている情報（PBI、要望、アイデア）を起点にする
2. **ギャップ分析** - PRDとして足りない情報を特定する
3. **徹底的な深掘り** - 曖昧な点をしつこく質問して明確化
4. **主語述語構造** - 機能要件は「〇〇がXXできる」「〇〇はXXする」形式で整理（主語はユーザー、システム等）

## ワークフロー

### Step 1: PBIの入力と分析

1. **PBIを受け取る**
   - ユーザーからPBI（テキスト、URL、スクリーンショット等）を受け取る
   - 「どんな形式でもOK。まずは持っている情報を全部ください」

2. **PBIの理解と要約**
   - 受け取ったPBIを要約して確認
   - 「こういう理解で合っていますか？」

3. **ギャップ分析**
   - PRDの各セクションに対して、足りない情報を特定
   - 足りない情報のリストを作成

---

### Step 2: 徹底的な深掘り質問

**各セクションについて、不足している情報を徹底的に質問する。**

#### 2.1 背景と目的の深掘り

**チェックポイント:**
- [ ] なぜこの機能が必要か明確か？
- [ ] 現状の課題は具体的か？
- [ ] 目標は測定可能か？

**深掘り質問例:**
- 「今、この機能がないことでユーザーはどう困っていますか？」
- 「この課題を放置するとどんな悪影響がありますか？」
- 「なぜ今このタイミングで取り組むのですか？」
- 「この機能が完成したら、何がどう変わりますか？」

---

#### 2.2 ユーザーストーリーの深掘り

**チェックポイント:**
- [ ] 誰が使うか明確か？
- [ ] 何をしたいか具体的か？
- [ ] なぜそれをしたいか理由があるか？

**深掘り質問例:**
- 「この機能を使うのは具体的にどんなユーザーですか？」
- 「そのユーザーは今、どうやってこの作業をしていますか？」
- 「その作業の何が不満・不便ですか？」
- 「この機能があれば、具体的にどう楽になりますか？」

---

#### 2.3 機能要件の深掘り（最重要）

**チェックポイント:**
- [ ] 「〇〇がXXできる」「〇〇はXXする」のような主語述語構造で書けているか？
- [ ] 主語（誰が/何が: ユーザー、システム等）は明確か？
- [ ] アクションは具体的か？
- [ ] 結果・状態変化は具体的か？
- [ ] 制約条件は明確か？

**深掘りカテゴリ:**

**1. 基本要素（誰が/何が・何を・どうする・どうなる）**
- 「主語は誰/何ですか？（ユーザー、システム、バッチ処理等）」
- 「ユーザーの場合、誰ですか？全員？ログインユーザーのみ？管理者のみ？」
- 「操作対象は何ですか？（データ、ファイル、設定など）」
- 「具体的なアクションは？（作成、更新、削除、検索、表示、通知など）」
- 「操作後、何がどう変わりますか？（結果は具体的に）」

**2. 入力・出力**
- 「ユーザーは何を入力しますか？」
- 「必須項目と任意項目は？」
- 「入力のバリデーションは？（文字数、形式など）」
- 「結果はどう表示されますか？」

**3. 制約条件**
- 「件数制限はありますか？（検索結果の上限など）」
- 「時間制限はありますか？（有効期限など）」
- 「自分のデータのみ？他人のデータも操作できる？」

**4. エラーハンドリング**
- 「どんなエラーが起こりえますか？」
- 「エラー時にユーザーに何を伝えますか？」
- 「リトライできますか？」

**5. エッジケース**
- 「データが0件のときはどうなりますか？」
- 「大量データ（数千件）のときは？」
- 「同時に複数人が操作したら？」

**6. 既存機能への影響**
- 「既存機能の挙動は変わりますか？」
- 「既存のデータ構造は変わりますか？」
- 「マイグレーションは必要ですか？」
- 「後方互換性は必要ですか？」

**7. UI/UX**
- 「画面のどこに配置しますか？」
- 「操作の流れは？」
- 「ローディング中の表示は？」
- 「成功・完了時のフィードバックは？」

**8. スコープ外の明確化**
- 「今回は含めない機能は何ですか？」
- 「ユーザーが期待しそうだけど対応しないものは？」
- 「将来追加したいけど今回は見送るものは？」

---

#### 2.4 非機能要件の深掘り

**チェックポイント:**
- [ ] パフォーマンス要件は数値化されているか？
- [ ] セキュリティ要件は明確か？

**深掘り質問例:**
- 「処理速度の目標はありますか？（○秒以内など）」
- 「認証は必要ですか？」
- 「データの暗号化は必要ですか？」

---

### Step 3: PRDの生成（日英両方）

1. **深掘り結果をPRD形式に整理**
   - 日本語版: `templates/prd-template.md` をベースに生成
   - 英語版: `templates/prd-template-en.md` をベースに生成
   - 機能要件は必ず主語述語構造

2. **ユーザーに確認**
   - 「このPRDで抜け漏れはありませんか？」

3. **修正・追加**
   - 不足があれば追加の深掘り

4. **ファイル保存（2ファイル）**
   - 日本語版: `PRD_[機能名]_YYYYMMDD.md`
   - 英語版: `PRD_[FeatureName]_YYYYMMDD_en.md`

---

## 使用方法

```
/prd-creator
```

**入力方法:**
- PBIのテキストをそのまま貼り付け
- JiraやNotionのURLを共有
- スクリーンショットを添付
- 口頭で説明

## 出力フォーマット

```markdown
# [機能名] - Product Requirements Document

## 1. 概要
## 2. 背景と目的
## 3. ユーザーストーリー
## 4. 機能要件
## 5. 非機能要件
## 6. 変更履歴
```

## サポートリソース

- `templates/prd-template.md` - PRDテンプレート（日本語）
- `templates/prd-template-en.md` - PRDテンプレート（English）
- `checklists/prd-sections.md` - 深掘りチェックリスト

## 出力言語

**日本語版と英語版の両方**を出力します。
