# Evidence Validation Checklist

このチェックリストは、指摘内容や提案の根拠が実際のコード上で妥当であるかを検証するために使用します。

## 1. 問題の再現可能性

### 1.1 指摘された問題が実コード上で確認できるか
- **検証方法**: `view_file` で該当箇所を確認
- **確認項目**:
  - 指摘された問題が実際に存在するか
  - 問題の説明と実際のコードが一致するか
  - 再現条件が明確に示されているか

### 1.2 問題の影響範囲が正確に把握されているか
- **検証方法**: `grep_search` で関連コードを検索
- **確認項目**:
  - 同様の問題が他にも存在しないか過小評価されていないか
  - 影響範囲が過大評価されていないか
  - 関連する問題が見落とされていないか

### 1.3 問題の重大度が適切に評価されているか
- **検証方法**: コードの文脈とアプリケーションの性質を考慮
- **確認項目**:
  - 致命的な問題を軽視していないか
  - 軽微な問題を過大評価していないか
  - ビジネスロジックへの影響が考慮されているか

## 2. 提案の文脈適合性

### 2.1 提案された修正が既存のコードスタイルに合致するか
- **検証方法**: 周辺コードのパターンを確認
- **確認項目**:
  - コーディング規約に従っているか
  - プロジェクトの命名規則に合致するか
  - 既存のアーキテクチャパターンと整合性があるか

### 2.2 提案が技術スタック・フレームワークに適合するか
- **検証方法**: プロジェクトの依存関係とフレームワークの推奨パターンを確認
- **確認項目**:
  - 使用しているフレームワークのベストプラクティスに従っているか
  - 利用可能なライブラリ機能を適切に活用しているか
  - 非推奨のAPIや古いパターンを提案していないか

### 2.3 提案が実装可能か
- **検証方法**: 依存関係と制約条件を確認
- **確認項目**:
  - 必要なライブラリやツールが利用可能か
  - 型システムの制約を満たしているか
  - パフォーマンスやセキュリティの要件を満たしているか

### 2.4 提案が他の部分に悪影響を与えないか
- **検証方法**: `grep_search` で影響範囲を調査
- **確認項目**:
  - 破壊的変更になっていないか
  - 他のコードへの依存関係が考慮されているか
  - 副作用が発生しないか

## 3. 論理的整合性

### 3.1 説明や推論に論理的飛躍がないか
- **検証方法**: 主張の因果関係を確認
- **確認項目**:
  - 「AだからB」という推論が論理的に妥当か
  - 根拠のない仮定に基づいていないか
  - 中間ステップが省略されていないか

### 3.2 主張が証拠によって裏付けられているか
- **検証方法**: 実際のコードを確認
- **確認項目**:
  - すべての主張に具体的なコード例があるか
  - コード例が主張を実際に裏付けているか
  - 反例が考慮されているか

### 3.3 技術的な説明が正確か
- **検証方法**: 技術的知識とドキュメントで確認
- **確認項目**:
  - 技術用語が正しく使用されているか
  - アルゴリズムやデータ構造の説明が正確か
  - フレームワークの動作説明が正しいか

## 4. 矛盾の不在

### 4.1 複数の指摘間で矛盾がないか
- **検証方法**: すべての指摘を横断的にレビュー
- **確認項目**:
  - ある指摘が別の指摘と矛盾していないか
  - 提案同士が相互に実装可能か
  - 優先度や重要度の評価に一貫性があるか

### 4.2 指摘内容と既存のコードベースの方針に矛盾がないか
- **検証方法**: プロジェクトのドキュメントや設計方針を確認
- **確認項目**:
  - コードベース全体の方向性と一致しているか
  - 既存の設計判断を尊重しているか
  - アーキテクチャの原則に反していないか

### 4.3 コード例と説明が一致しているか
- **検証方法**: コード例を詳細に読み、説明と照合
- **確認項目**:
  - コメントとコードが一致しているか
  - 説明文で言及している動作をコードが実際に行うか
  - Before/Afterの比較が正確か

### 4.4 前提条件と結論が整合しているか
- **検証方法**: 論理的な流れを追跡
- **確認項目**:
  - 前提条件が正しく識別されているか
  - 前提が変わった場合の影響が考慮されているか
  - 結論が前提から論理的に導かれているか

## 検証ステータス定義

- **✅ VERIFIED**: 指摘内容が実コード上で確認でき、提案が文脈に適合し、論理的に整合している
- **⚠️ INVALID**: 問題が再現できない、提案が不適切、論理的矛盾がある
- **🔶 REQUIRES_CONFIRMATION**: 追加の文脈情報や技術的判断が必要
