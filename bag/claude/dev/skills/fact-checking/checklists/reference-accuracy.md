# Reference Accuracy Checklist

このチェックリストは、コード分析やレビューにおける参照の正確性を検証するために使用します。

## 1. ファイルパスの実在性

### 1.1 参照されたファイルが実際に存在するか
- **検証方法**: `find_by_name` または `view_file` で確認
- **確認項目**:
  - ファイルパスが正確か
  - 相対パス/絶対パスの使用が適切か
  - タイポや誤ったディレクトリ参照がないか

### 1.2 ファイル拡張子が正しいか
- **検証方法**: ファイル存在確認時に拡張子も検証
- **確認項目**:
  - `.ts` と `.tsx` の混同がないか
  - `.js` と `.jsx` の混同がないか
  - その他の拡張子の誤りがないか

## 2. クラス/関数の実在性

### 2.1 参照されたクラスが実際に定義されているか
- **検証方法**: `grep_search` でクラス定義を検索、または `view_code_item` で確認
- **確認項目**:
  - クラス名が正確か（大文字小文字含む）
  - 該当ファイル内にクラスが定義されているか
  - export されているか（必要な場合）

### 2.2 参照された関数/メソッドが実際に定義されているか
- **検証方法**: `grep_search` で関数定義を検索、または `view_code_item` で確認
- **確認項目**:
  - 関数名が正確か
  - 該当クラス内/ファイル内に関数が存在するか
  - シグネチャ（引数、戻り値型）が正しく参照されているか

### 2.3 インポート/エクスポートの整合性
- **検証方法**: `grep_search` でimport/export文を確認
- **確認項目**:
  - 参照されたコードが適切にexportされているか
  - import パスが正確か
  - 名前付きエクスポート/デフォルトエクスポートの区別が正しいか

## 3. コードスニペットの一致性

### 3.1 引用されたコードが実際のコードと一致するか
- **検証方法**: `view_file` で実際のコードを確認し、行単位で比較
- **確認項目**:
  - コードの内容が完全に一致するか
  - インデントが正しく保持されているか
  - コメントも含めて一致するか

### 3.2 コードスニペットの文脈が適切か
- **検証方法**: スニペットの前後のコードも確認
- **確認項目**:
  - コードが文脈から切り離されていないか
  - 省略されている部分が重要な情報を含んでいないか
  - スニペットの範囲が適切か

### 3.3 構文エラーがないか
- **検証方法**: コードの構文をチェック
- **確認項目**:
  - 引用時に構文が壊れていないか
  - 括弧の対応が正しいか
  - 不完全なコードブロックになっていないか

## 4. 行番号参照の正確性

### 4.1 指定された行番号が正しいか
- **検証方法**: `view_file` で行番号を指定して確認
- **確認項目**:
  - 行番号が実際にその内容を指しているか
  - 範囲指定（L10-L20など）が正確か
  - 1-indexed/0-indexedの混同がないか

### 4.2 行番号が最新のコードベースと一致するか
- **検証方法**: 現在のファイル内容と照合
- **確認項目**:
  - コードの変更により行番号がずれていないか
  - 古い情報を参照していないか
  - 複数箇所で同じ内容がある場合、正しい箇所を指しているか

### 4.3 行範囲が妥当か
- **検証方法**: 指定範囲のコードを確認
- **確認項目**:
  - 範囲が短すぎて文脈不足になっていないか
  - 範囲が長すぎて関係ないコードを含んでいないか
  - 論理的なコードブロックと一致しているか

## 検証ステータス定義

- **✅ VERIFIED**: すべての参照が実際のコードベースと完全に一致している
- **⚠️ INVALID**: 参照に誤りがある（ファイル不存在、クラス/関数名の誤り、コード不一致など）
- **🔶 REQUIRES_CONFIRMATION**: 検証には追加情報が必要、または文脈的判断が必要
