# Impact Assessment Checklist

このチェックリストは、コード変更の影響範囲評価が正確で完全であるかを検証するために使用します。

## 1. 依存関係の実在確認

### 1.1 言及された依存関係が実際に存在するか
- **検証方法**: `grep_search` でimport文や使用箇所を検索
- **確認項目**:
  - 依存関係が実際のコードで確認できるか
  - import/export/require文が存在するか
  - モジュール間の依存が正確に把握されているか

### 1.2 依存の方向性が正しいか
- **検証方法**: コードの構造を確認
- **確認項目**:
  - AがBに依存しているのか、BがAに依存しているのか正しく識別されているか
  - 循環依存が見落とされていないか
  - 依存の深さ（直接/間接）が正確に評価されているか

### 1.3 すべての依存関係が網羅されているか
- **検証方法**: `grep_search` で包括的に検索
- **確認項目**:
  - 見落とされた依存関係がないか
  - 暗黙的な依存（グローバル変数、シングルトンなど）が考慮されているか
  - 実行時依存（dynamic import、リフレクションなど）が含まれているか

## 2. 影響対象ファイルの妥当性

### 2.1 リストされた影響対象ファイルが実在するか
- **検証方法**: `find_by_name` でファイルの存在を確認
- **確認項目**:
  - すべてのファイルパスが正確か
  - ファイルが削除されていないか
  - ディレクトリ構造の変更が反映されているか

### 2.2 影響対象として挙げられたファイルが実際に影響を受けるか
- **検証方法**: `grep_search` で変更箇所への参照を確認
- **確認項目**:
  - ファイルが実際に変更されたコードを使用しているか
  - 直接的な影響か間接的な影響かが明確か
  - 影響の種類（動作変更、インターフェース変更など）が正しく識別されているか

### 2.3 影響を受けるが挙げられていないファイルがないか
- **検証方法**: `grep_search` で広範囲に検索
- **確認項目**:
  - テストファイルが含まれているか
  - 設定ファイルへの影響が考慮されているか
  - ドキュメントの更新が必要かどうか評価されているか

### 2.4 影響の程度が適切に評価されているか
- **検証方法**: コードの使用状況を詳細に確認
- **確認項目**:
  - 軽微な影響と重大な影響が区別されているか
  - 破壊的変更が明確に示されているか
  - 段階的移行が可能かどうか評価されているか

## 3. リスク評価の根拠明示

### 3.1 リスク評価に具体的根拠があるか
- **検証方法**: リスク評価の各項目を実コードと照合
- **確認項目**:
  - 「高リスク」「低リスク」の判断基準が明確か
  - リスク評価が推測ではなく事実に基づいているか
  - コードの複雑さ、使用頻度などの定量的指標があるか

### 3.2 技術的リスクが適切に識別されているか
- **検証方法**: コードとアーキテクチャを分析
- **確認項目**:
  - パフォーマンスへの影響が評価されているか
  - セキュリティリスクが考慮されているか
  - データ整合性への影響が検討されているか
  - 後方互換性が評価されているか

### 3.3 ビジネスリスクが考慮されているか
- **検証方法**: 機能とビジネスロジックの関連性を確認
- **確認項目**:
  - クリティカルなビジネス機能への影響が評価されているか
  - ユーザー体験への影響が考慮されているか
  - ダウンタイムやデプロイリスクが検討されているか

### 3.4 リスク軽減策が提案されているか
- **検証方法**: 提案内容の実現可能性を確認
- **確認項目**:
  - 具体的な軽減策が示されているか
  - フィーチャーフラグやカナリアリリースなどの戦略が検討されているか
  - ロールバック計画があるか

## 4. 影響範囲の完全性

### 4.1 コード以外の成果物への影響が評価されているか
- **検証方法**: プロジェクト全体を俯瞰
- **確認項目**:
  - ドキュメントの更新が必要か
  - APIスキーマやデータベーススキーマへの影響があるか
  - 設定ファイルやデプロイスクリプトの変更が必要か

### 4.2 開発環境・ビルドプロセスへの影響が考慮されているか
- **検証方法**: ビルド設定やCI/CD設定を確認
- **確認項目**:
  - 依存パッケージの追加/更新が必要か
  - ビルド設定の変更が必要か
  - テスト実行への影響があるか

### 4.3 外部システムとの統合への影響が評価されているか
- **検証方法**: 外部連携コードを確認
- **確認項目**:
  - API契約の変更があるか
  - 外部サービスとの連携に影響があるか
  - データフォーマットの変更があるか

### 4.4 時系列的な影響が考慮されているか
- **検証方法**: デプロイ戦略を検討
- **確認項目**:
  - 段階的なロールアウトが必要か
  - 移行期間中の互換性が保たれるか
  - 既存データの移行が必要か

## 検証ステータス定義

- **✅ VERIFIED**: 依存関係が確認され、影響対象が正確に識別され、リスク評価に根拠がある
- **⚠️ INVALID**: 依存関係の誤り、影響範囲の漏れ、根拠のないリスク評価がある
- **🔶 REQUIRES_CONFIRMATION**: 追加調査が必要、またはビジネス判断が必要
