# Comprehensive Code Review Workflow

## 実行手順

### Step 1: レビュー対象の確定

以下のいずれかでレビュー対象を特定する：
- `$ARGUMENTS` で渡されたPR URL / commit hash / ディレクトリ / ファイル
- `gh pr view --json` で現在のブランチのPRを取得
- `git status` / `git diff` で未コミットの変更を確認

**対象が曖昧または未指定の場合**：ユーザーに確認を求めて中断する。

### Step 2: 並列レビュー

以下の2つのレビューを**並列で**実行する：

- **@code-reviewer**: コード品質レビュー（実装品質、可読性、型、テスト）
- **@architecture-reviewer**: アーキテクチャレビュー（責務分離、依存関係、循環依存）

### Step 3: ファクトチェック

- **@fact-checker**: Step 1 の両レビュー結果を検証
  - ファイル参照・コード行の実在性確認
  - 依存関係の事実確認

### Step 4: 結果表示

```markdown
# レビュー結果

## 概要
- レビュー対象: [対象]
- 検出された問題数: [件数]

## 要修正事項
[優先度順に列挙]

### 1. [問題の要約]
- **場所**: [ファイルパス:行番号]
- **詳細**: [問題点と改善案]
- **修正プロンプト**:
  ```
  [そのまま実行可能な修正指示]
  ```

## 詳細

### Code Review
[検証済みのコードレビュー結果]

### Architecture Review
[検証済みのアーキテクチャレビュー結果]
```
